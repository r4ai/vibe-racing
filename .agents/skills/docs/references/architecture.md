# アーキテクチャ文書の設計基準

システム全体（`docs/architecture.md`）および各モジュール（`**/docs/architecture.md`）の設計文書に適用する構成規範である。
`matklad` 式 `ARCHITECTURE.md`（コード地図と不変条件）と C4 Model・Views & Beyond（静的・動的・実行時視点の分離）を基礎とする。

## 基本方針

- **対象読者**: 開発者、コントリビューター、コーディングエージェント
- **目的**: 対象スコープの全体像、境界ルール、変更箇所の地図を短時間で掴める状態にする
- **書かないもの**:
  - 実装済み・未実装の一覧、TODO、移行の経緯メモ
  - マニフェストやコードを見れば分かる自明な細部、関数単位の変更頻度の高い解説
  - 長大な設計背景・対案比較（必要に応じて別文書へ分離）

## 章立て構成

以下の章立てを順守する（見出しに連番は付けない）。対象スコープで不要な小節は省く。

### 概要と基本概念

- 対象システムの目的と基本構成（2〜4 文）
- **基本モデル**: 中核となる設計概念を構造化箇条書きで整理
- **設計目標**: 重視する品質特性（信頼性、拡張性、応答性、省資源等）
- **用語**: 固有語・略語の定義表

### 階層構造と実行時アーキテクチャ

抽象・制御の階層と、実行時の境界・配置を分けて示す。

- **全体の階層構造**:
  - 上位層から下位層への積み上げ図
  - 内部に複数の階層を持つ層は、ネスト等で内部の階層関係まで明示
  - 静的インポートの向きと逆転（DIP）がある場合の注記
- **実行時の構成**:
  - 実行単位（プロセス・スレッド・タスク等）の境界、通信路、永続ストア、外部依存との接続図
  - 実行単位ごとの技術形態・役割・生存期間をまとめた表
- **境界と永続化**: 通信境界・プロトコル・永続データの所有関係を整理

### コードマップと依存関係

- **依存の向き**:
  - 静的インポート（パッケージ・モジュール・ファイル間）に基づく有向非巡回グラフ図
  - 逆依存を禁止する仕組みや境界契約の置き方
- **構成要素の対応**: 層・対象パス・1 行責務・変更頻度・詳細文書へのリンクをまとめた単一の索引表

### 設計上の不変条件

変更時に破ってはいけない境界・構造ルールを列挙する。

- 外部・上位層へ依存しない独立モジュールの範囲
- 抽象契約により具体実装から切り離す領域
- 状態や権限などの正本（Single Source of Truth）の所在
- 互換性や検証を担保するための隔離箇所

### 主要な処理フロー

代表的なユースケースを 2〜3 本選び、シーケンス図で追う。

- 外部入力や要求を受け付けて状態変更・出力へ至る主要経路
- 非同期処理、状態同期、エラー・再同期などの境界を跨ぐ流れ

### 横断的設計トピック

特定の 1 ファイルや 1 モジュールに閉じない横断事項を小節でまとめる。

- セキュリティ境界、権限モデル、拡張方式
- 永続化、障害復旧、エラー処理方針
- 性能・メモリ・描画など、構造に起因する制約（実測事実や確定仕様のみ、未実装項目は除外）

### 関連文書

単体仕様や補足資料など、構成要素の一覧表からリンクしていない横断・詳細文書への案内表。
一覧表と重複するリンクは載せない。
